Calibration in Husky Teleop

Every pose in this project lives in one world frame: the OptiTrack (Motive) origin, turned Z-up. To place a robot in it, the monitor multiplies a chain of transforms, from the Husky's mocap tracker down to the gripper tip. Our own pipeline calibrates exactly one link of that chain, base_mocap_from_base_footprint. The arm kinematics come from the UR factory, the punch tip from the teach pendant, and everything else from the URDF and the tool models.

Measured and calibrated

  • Base tracker to robot. Our pipeline: turn J0, then J1, with a mocap tool on the flange, fit circles, and build the arm base frame from the two axes. One file per robot and date.
  • Arm joints. The UR factory calibration of each UR5e, copied by hand into the *_Calibrated.urdf joint origins. ssik is built from the same URDFs.
  • Cindy's right arm relative to her left. Both probe tips touched the same 10 points (2025-08). The result sits in right_arm_mount_joint.
  • Punch tip. The pendant's 4-point TCP wizard, saved per date in config.yaml. The punch only checks the base calibration.

Taken as drawn

  • Arm mount on the Husky. URDF values. Mount errors cancel for the calibrated arm, because the pipeline measures that arm's base directly.
  • Tool and gripper tips. AT3L/AT3R from their tool models, the Robotiq tip as a constant in utils.py.
  • The grasp. Each bar's attachment_frame comes from the Rhino export.
  • The room. The Rhino design world is assumed to be the mocap world, and the floor height comes from WalkableGround.json.

The base calibration, step by step

Data is captured in the monitor, then five offline scripts in data/calibration_data/ turn it into one transform. The middle lane is the code; the top lane is what it writes to the date folder, the bottom lane the frame math it does.

  1. Capture

    The batch slider picks j0, j1, validation or punch_validation __init__.py:111. For j0 and j1 the monitor plays 6 trajectories of 31 waypoints each and records one sample per waypoint after it settles husky_world.py:1419. On J0 sweeps only J0 turns, about 360°; on J1 sweeps only J1 turns, about 190°, with J0 at 0. Validation samples are clicked by hand at varied base spots. calibrate_button husky_world.py:834 refuses a sample unless both rigid bodies are fresher than CALIB_MOCAP_MAX_AGE_S husky_world.py:72.

    sample = {joint_conf, base_mocap_pose, flange_mocap_pose}, poses in world

  2. Circle fit

    Each flange-marker position is first written in the Husky tracker's frame, which removes any sway of the base calibration_data/0_circle_fitting.py:77. Circle3D calibration_data/0_circle_fitting.py:83 fits a plane, then a circle in it, for each take.

    base_mocap_from_flange_mocap = inverse(world_from_base_mocap) · world_from_flange_mocap take k → centre c_k, normal n_k, radius r_k (in base_mocap)

  3. Base frame

    fit_line_to_centers calibration_data/1_calibration_analysis.py:430 turns the centres of one joint's takes into its axis line. A fitted line has no sign, so joint_axis_from_motion calibration_data/1_calibration_analysis.py:499 picks it from how the tool turned as the joint angle grew (right-hand rule), and compute_base_frame calibration_data/1_calibration_analysis.py:533 builds the frame. The geometry is drawn in Figure 3.

    v0 = mean n_k (J0 takes), p0 = mean c_k; v1, p1 likewise for J1 Z = +J0, Y = −J1, X = Y × Z, origin p_b = p01 − base_offset · Z

  4. Add the URDF

    The result of step 3 is the pose of the arm's base_link_inertia. The monitor needs the URDF root, so the fixed URDF transform between the two is multiplied on calibration_data/2_convert_and_visualize_transformation.py:103, taken from the robot's own calibrated URDF calibration_data/2_convert_and_visualize_transformation.py:98.

    base_mocap_from_base_footprint = base_mocap_from_arm_base_link_inertia · arm_base_link_inertia_from_base_footprint (URDF)

  5. Validate

    3_verify_calibration.py runs the validation batch through the new calibration calibration_data/3_verify_calibration.py:116. If the calibration is right, the marker sits at the same place on the flange in every sample calibration_data/3_verify_calibration.py:126; the goal is 95 % under 5 mm and 0.3° calibration_data/3_verify_calibration.py:439. 4_punch_validation.py asks the same of the punch tip touching one fixed point from many base poses calibration_data/4_punch_validation.py:127.

    tool0_from_flange_mocap = inverse(world_from_base_footprint · FK(q)) · world_from_flange_mocap world_from_punch_tip = world_from_base_footprint · FK(q) · tool0_from_punch_tip

  6. Use at run time

    _base_calibration_file_for husky_world.py:234 picks the file of the robot's pinned date. Only one key is read from it common.py:385. Then every mocap frame places the robot husky_monitor.py:12347. Tracked tools, such as the calib tool, get their raw world poses.

    world_from_base_footprint = world_from_base_mocap · base_mocap_from_base_footprint

Gotchas

Things that have broken a calibration before, or that are easy to get wrong.

  • fixed three times

    A fitted axis has no sign

    Each wrong sign rotated the whole base frame: a 90° roll on Cindy (2026-06-26, the robot lay on the floor in PyBullet), a 90° yaw on Alice (2026-07-02), a 180° yaw on Belle, whose tracker is mounted the other way round (2026-10-14). The yaw cases look clean in roll and pitch. The fast check for any new calibration is the mean marker offset on the J0/J1 data: it should be 22–24 mm. Metres mean a flipped axis.

  • capture

    The mocap cache keeps the last pose of a lost body

    Belle's first validation set was ruined by a tool pose that had stopped updating. calibrate_button now refuses samples older than 0.5 s. There is still no time sync between the joint state and the mocap pose, so let the arm settle before each sample.

  • capture

    j0/j1 store the commanded angles, validation the measured ones

    On the sweeps, joint_conf is the waypoint that was sent, written just before recording. On validation it is the live joint state.

  • pendant

    The pendant TCP must be the zero tool

    The monitor compares the driver's tcp_pose with FK tool0. A pendant with the punch or gripper TCP active shows up as a constant offset along tool Z ("not in correct start pose!"). Check the pendant before hunting for a frame bug.

  • scope

    The marker offset is checked, never solved

    tool0_from_flange_mocap is only required to stay constant. Its mean is logged but not saved, and nothing downstream uses it. The calibration-tool visualisers that anchor the arm on the marker are therefore only approximate.

  • dates

    Newer is not better: dates are per robot

    Recording uses CALIBRATION_DATE, the offline scripts use CALIBRATION_ANALYSIS_DATE, and each robot reads its own BASE_CALIBRATION_DATE_BY_ROBOT entry. After a new calibration, point that robot's entry at the new folder and turn calibration mode off again (doc/calibration_manual.md §4.0).

  • limits

    The servo loop cannot see calibration error

    The visual servo compares FK with the target, and FK already uses the base calibration, the arm kinematics and the tool model. In session 20261001 the servo residual was 0.23–1.24 mm while the bars landed 2.6–6.6 mm off. Errors in this chain only show up in an outside measurement, such as the bar marker rig or the punch.
