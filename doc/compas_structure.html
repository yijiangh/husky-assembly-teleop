COMPAS in Husky Teleop

In this project COMPAS is the data model and the collision checker. Every scene, robot state, target and saved plan is a COMPAS object stored as COMPAS JSON, and compas_fab's PyBullet backend runs every collision check. Path search, IK and everything that talks to the robots use other libraries. Values cross over to them as numpy arrays and pybullet_planning poses.

COMPAS does

  • Describe the scene. A RobotCell holds the robot, its tools, every bar and the floor. A RobotCellState says where each one is, what is attached and what is allowed to touch.
  • Carry the data. Actions, movements, targets and saved plans are COMPAS objects, read and written with json_load and json_dump.
  • Check collisions. check_collision answers for every planner, ours and tamp's.
  • Plan support-robot straight lines. plan_cartesian_motion, single arm only.

COMPAS does not

  • Search for paths. pybullet_planning's BiRRT does. compas_fab's plan_motion is never called.
  • Solve most IK. ssik's analytic solvers do. compas_fab IK is the fallback.
  • Compute FK while planning. tamp reads link poses straight from PyBullet.
  • Talk to the robots. husky_robot.py publishes numpy arrays on ROS2 topics, and mocap arrives as pybullet_planning poses.

The stack

Three COMPAS packages sit under our code. We use compas_fab in two ways: its robots module is our data model, and its PyBullet backend is our collision engine.

One movement, end to end

What happens to one movement, from the exported file to the robot and back. The middle lane is where the movement's state lives between steps.

  1. Load

    CfabSession cfab_session.py:284 loads the robot's own cell with json_load: RobotCell.json for Cindy, RobotCell_<Name>.json for a support robot robot_registry.py:288. It adds the floor as rigid body obstacle_ground cfab_session.py:178 and calls set_robot_cell cfab_session.py:353. parse_bar_action bar_action_io.py:118 rebuilds the action and its movements.

  2. Sync with live

    Joints arrive in arm_callback husky_robot.py:697, the calibrated base pose in receive_mocap_frame husky_monitor.py:12035. _inject_live_conf_into_state husky_monitor.py:3288 writes both into the RobotCellState. apply_obstacle_robot_beliefs cfab_session.py:753 places the other robots, inject_ground_rigid_body_state cfab_session.py:237 adds the floor, and load_selected_movement husky_monitor.py:3930 applies the state with set_robot_cell_state.

  3. Plan

    _plan_by_kind husky_monitor.py:4159 picks the planner from the movement's class (see Planners). The planner gets the compas_fab planner, the start RobotCellState and the goal. It searches with pybullet_planning, solves IK with ssik and tests every candidate with check_collision, wrapped by _build_cfab_collision_fn tamp/motion_planner/api.py:128.

  4. Accept + save

    The path, a list of 12 joint values per point, becomes a JointTrajectory through joint_trajectory_from_path utils.py:156. _accept_trajectory husky_monitor.py:5838 stores it and carries the end configuration into the next movement. _write_action_halves_for husky_monitor.py:6495 saves the action with json_dump to *.live-solved.json.

  5. Execute

    path_12_from_joint_trajectory utils.py:238 turns the plan back into numpy. execute_arm_trajectory_all husky_world.py:2412 calls send_dual_arm_cmd husky_robot.py:1005, which publishes on <ns>/multi_arm_joint_trajectory. Single-arm robots use send_arm_cmd husky_robot.py:1053. Compliant moves send PoseStamped targets on <arm>/target_frame husky_robot.py:833.

  6. Hand over

    _propagate_live_end husky_monitor.py:6116 copies the live joints and base into the next movement's start state and saves this robot's belief to progress.json with save_progress progress_io.py:470, which writes with json_dumps.

Two robots in one PyBullet window

The monitor window draws two copies of the robot on top of each other. Only one of them is what the planner checks.

Gotchas

Things in the COMPAS layer that have caused trouble or will.

  • upstream bug

    compas_fab's forward kinematics applies the robot base twice

    It multiplies a link pose that is already in world coordinates by robot_base_frame again compas_fab/backends/pybullet/backend_features/pybullet_forward_kinematics.py:100. Planning avoids it, because tamp's _fk_link_frame reads link poses from PyBullet. For plan_cartesian_motion we swap in a fixed copy with _world_frame_forward_kinematics cfab_session.py:665. A second upstream bug reads the position tolerance from the orientation tolerance, which is why both are set equal cfab_session.py:720.

  • install

    compas_fab is a copied install

    The venv's compas_fab was installed from external/compas_fab without -e. Editing the submodule changes nothing until you reinstall it. tamp and rs_data_structure are editable installs, so their edits apply at once.

  • invariant

    The cell and every state must list the same rigid bodies

    compas_fab rejects a state that does not match its cell. CfabSession adds the floor to the cell cfab_session.py:351, so every state needs inject_ground_rigid_body_state cfab_session.py:237 before it is applied.

  • private API

    We depend on underscore names

    The teleop imports private functions from tamp (_build_cfab_collision_fn, _state_with_conf12, _fk_link_frame, _derive_constrained_start_for_plan). It passes the fork's private options _skip_cc1 to _skip_cc5 and _skip_set_robot_cell_state husky_monitor.py:2483, and it replaces _build_cfab_collision_fn at runtime in _free_planner_skip_env_collisions husky_world.py:2600. An upgrade of compas_fab or tamp can break these without any import error.

  • dead code

    COMPAS imports and helpers nobody calls

    Transformation is imported but unused husky_monitor.py:98. pose_from_transformation and transformation_from_pose are imported husky_monitor.py:55 but never called, and conf_from_6vec utils.py:134 has no callers. import compas husky_world.py:48 only serves load_robotcellstate_and_update_goal husky_world.py:2515, whose button is commented out. tamp's get_joint_collision_fn_cfab tamp/motion_planner/dual_arm_task_space_rrt/core.py:795 imports husky_assembly_teleop.cfab_collision_adapter, which does not exist.
